Description

This package provides a collection of tools for neural-network-based hyper-reduction and nonlinear reduced-order modelling components for GridapROMs.jl.

Manual

NonlinearROMs.NonlinearROMs — Module
module NonlinearROMs

Neural-operator surrogates for parameterised PDEs, built on Gridap.jl and GridapROMs.jl.

  • Data — InputSpace/OutputSpace evaluate coordinates, a FeatureBundle of parameterised coefficients and FE solutions as (D,N,K) arrays; to_element maps predictions back to FEFunctions.

  • Models — KernelNeuralModel: kernel neural operators, with the integral kernel discretised by FE quadrature (FunctionSpace) or on a radius graph (GraphInducedSpace, MultiGraphInducedSpace), or spectral (FourierStyle); multi-field problems and several meshes are handled by gluing local spaces into a MultipleSpaces.

  • Training — NeuralSolver/neural_operator train through a Lux/Reactant/Enzyme pipeline, with configurable normalisation and EnergyLosses in the norms of the FE space; RolloutNeuralSolver trains autoregressive operators for transient problems (RolloutData).

A learning rate scheduler that implements a Cosine Annealing decay schedule. It smoothly decreases the learning rate from a maximum value down to a minimum value, following the shape of a half-cosine wave over total_epochs epochs.

Fields / Keyword Arguments

  • total_epochs::Int: The total number of training epochs the schedule decays over (required positional argument).
  • lr_max::TData: The initial, peak learning rate (default: TData(0.001)).
  • lr_min::TData: The final, minimum learning rate at the end of training (default: TData(1e-6)).

NonlinearROMs.FourierKernel — Type
struct FourierKernel <: AbstractIntegralKernel
  in_dims::Int
  out_dims::Int
  truncation::Int
end

FNO-style spectral convolution (Li et al.): v of size (in_dims,N,K) is Fourier-transformed along the point axis, its first truncation modes are mixed across channels by one real (out_dims,in_dims) matrix per mode (the remaining modes are zeroed), and the result is transformed back to N points. Real per-mode weights scale the real and imaginary parts of each mode alike: in physical space they give an even (symmetric) convolution kernel.

The FFT treats the N points as uniformly spaced samples in the order they are stored, so the kernel is only a convolution in physical space if the points are ordered on a uniform 1D grid; for any other point set it is a (still trainable) global operator whose meaning depends on the point ordering.

NonlinearROMs.GenericNeuralSolver — Type
struct GenericNeuralSolver{A<:NeuralModel} <: NeuralSolver
  model::A
  epochs::Int
  batch_size::Int
  formatter::DataFormatter
  optimiser::Optimiser
  loss::Function
  trainlog::TrainingLog
end

NeuralSolver(
  model::NeuralModel;
  epochs::Int=20000,
  batch_size::Int=0,
  formatter=DataFormatter(model),
  lr_scheduler=CosineAnnealing(epochs),
  loss=Lux.MSELoss(),
  name=string(nameof(typeof(model))),
  verbose::Bool=true,
  print_every::Int=500,
  kwargs...
  )

The Reduced Basis Solver for Neural Operators: bundles a neural architecture with its training hyperparameters. The keyword constructor is the intended entry point: it builds the optimiser/trainlog fields from lr_scheduler(;kwargs...) and verbose/print_every respectively.

Arguments

  • model: Any NeuralModel architecture — DeepONet/NOMAD, MultiLayerPerceptron, AutoEncoder/AutoDecoder/ VariationalAutoEncoder, or a KernelNeuralModel.
  • epochs::Int: Total number of training epochs. Default: 20000.
  • batch_size::Int: The batch size for training. If 0 (or negative), defaults to the total number of available samples (full-batch). Default: 0.
  • formatter::DataFormatter: Controls which of the model's (coords,features) inputs are passed/sampled. Default: DataFormatter(model).
  • lr_scheduler: The learning rate scheduler to use (e.g., CosineAnnealing(epochs), ReduceLROnPlateau()). Default: CosineAnnealing(epochs).
  • loss: The training loss. Default: Lux.MSELoss().
  • verbose::Bool: If true, prints compilation times, training progress, and loss metrics. Default: true.
  • print_every::Int: Frequency (in epochs) of the training progress output. Default: 500.

Examples

Minimal Default Initialization:

# Default hyperparameters (20000 epochs, full-batch, etc.)
solver = NeuralSolver(DeepONet(2,2))

Custom Initialization:

using Lux

solver = NeuralSolver(
  DeepONet(2,2;width=128,depth=4,activation=Lux.gelu),
  epochs=1000
)

NonlinearROMs.IntegralKernel — Type
struct IntegralKernel{A<:AbstractLuxLayer,B<:InducedMeasure,C<:DataFormatter} <: AbstractIntegralKernel
  kernel::A
  measure::B
  formatter::C
  coord_dims::Int
end

Wraps a plain network kernel into a non-local integral operator (K v)(x) = ∫ κ_θ(x,y,...) v(y) dy, discretised by measure. Called as l((fixed_data,v),ps,st): fixed_data is the per-sample-fixed (x,a(x)) tensor assembled once upstream (see DataInterface.fetch_data), v is the running hidden state from the previous layer. formatter (its own, layer-local DataFormatter) decides which of (x,a(x))/v actually get concatenated and fed to kernel – different layers legitimately want different subsets (Kovachki et al.'s three kernel cases κ(x,y)/κ(x,y,a(x),a(y))/κ(x,y,v(x),v(y)) are exactly a choice of formatter). coord_dims is how many of fixed_data's leading rows are coordinates (vs. features), which formatter's pass_coords/pass_features use to select which part of fixed_data to keep (see DataInterface.merge_data). fixed_data passes through unchanged so the next layer can use it too.

NonlinearROMs.KernelNeuralLayer — Type
struct KernelNeuralLayer{A<:AbstractIntegralKernel,B<:Function} <: AbstractLuxLayer
  kernel::A
  in_dims::Int
  out_dims::Int
  activation::B
end

One iterative layer of a kernel neural operator (Kovachki et al.):

v_{t+1}(x) = σ(W v_t(x) + (K_t v_t)(x) + b(x))

kernel (K_t) is the non-local integral operator – any AbstractIntegralKernel (IntegralKernel wrapping a graph/FE-quadrature InducedMeasure, FourierKernel, AttentionKernel, ...). The pointwise local linear term W, bias b, and nonlinearity σ are owned by this layer, not by kernel, since they're the same shape/role regardless of which non-local discretization kernel uses. Called as l((fixed_data,v),ps,st): v feeds both the local W v term and kernel directly; fixed_data (the per-sample (x,a(x)) tensor) is only relevant to kernel (via its own formatter) and passes through untouched, so the next layer in the stack can use it too.

in_dims/out_dims are the running hidden state's channel counts (v_t's and v_{t+1}'s), sizing W/b – not kernel's own internal input width. kernel's network sees merge_data'd/gathered data (often v's channels plus fixed_data's, doubled again by gather_data for a graph measure), a completely different, independently-sized tensor; get_in_dimension(l.kernel) reports that internal width, not v's, so it must not be used to size W.

NonlinearROMs.KernelNeuralModel — Type
struct KernelNeuralModel{A<:KernelStyle,N,B<:Function,C<:DataFormatter,M,D<:Function} <: NeuralModel
  style::A
  hidden_layers::NTuple{N,Int}
  activation::B
  formatter::C
  kernel_layers::NTuple{M,Int}
  kernel_activation::D
end

Recipe for a kernel-based neural operator (Kovachki et al.), in the same spirit as NOMAD/MultiLayerPerceptron: hidden_layers only holds the hidden widths, with the input/output dimensions inferred from the training data at build_model time. style picks the non-local discretisation shared by every hidden layer (IntegralStyle for a graph/FE-quadrature InducedMeasure, FourierStyle for an FNO-style spectral kernel). formatter is the kernel-side DataFormatter: inside every hidden layer, pass_coords/pass_features select which channels of the fixed per-sample input (x,a(x)) are fed to κ_θ, and pass_new_data whether the running hidden state v is folded in too (e.g. pass_features=Val(false) gives Kovachki et al.'s κ(x,y) case). What the fixed input itself is made of is decided by the NeuralSolver's own formatter, which by default passes both x and a(x). kernel_layers/kernel_activation are the hidden widths/nonlinearity of κ_θ's own network; the default () makes κ_θ a single affine Dense, which cannot represent a non-affine kernel such as a Green's function.

build_model turns this recipe into an actual Lux.Chain:

  1. Lifting (P): a local Dense layer mapping the fixed input to the first hidden width.
  2. Iterative Kernel Integration: a stack of KernelNeuralLayers (one per interior hidden-width transition) performing the non-local processing.
  3. Projection (Q): a local Dense layer mapping the final hidden state to the output dimension.

NonlinearROMs.MultipleMeasure — Type
const MultipleMeasure = InducedMeasure{<:MultipleSpaces,<:Tuple}

Measure induced by a MultipleSpaces of FunctionSpaces or GraphInducedSpaces, weights holding one entry per local space. Its edges are those of the local measures (see get_local_measures), concatenated block by block and relabelled with the global vertex ids, so gather_data/kv work on the global, vertex-indexed data as for any other measure. Integration is carried out block by block on the local measures, then

  • summed over the blocks when the local spaces share their samples (multi-field);
  • concatenated along the sample axis otherwise (one block of samples per local space, e.g. several PDEs on a moving geometry), so that every sample is integrated on its own local measure only. The samples are then tied to the blocks, and cannot be batched.

NonlinearROMs.MultipleSpaces — Type
struct MultipleSpaces{N,A<:DiscreteSpace,B<:NTuple{N,DiscreteSpace},C<:Table,D<:Union{Nothing,AbstractVector{<:Integer}}} <: DiscreteSpace
  gspace::A
  lspaces::B
  l_to_lcoord_to_coords::C
  l_to_sample_offset::D
end

N local spaces lspaces glued into the global space gspace, which lives on the union of the local point sets. Covers two scenarios:

  • one PDE on a multi-field FE space (l_to_sample_offset === nothing): every local space (one per field) sees the same samples. Training data is laid out on the global points, with channels concatenated field by field (a point only some fields reach is zero-filled in every other field's channels);
  • several PDEs (e.g. on a moving geometry, l_to_sample_offset isa AbstractVector): every local space comes with its own samples, and the global samples l_to_sample_offset[l]:l_to_sample_offset[l+1]-1 are those of lspaces[l] (zero-filled outside of lspaces[l]'s points).

l_to_lcoord_to_coords[l] maps the points of lspaces[l] to those of gspace.

Built by InputSpace/OutputSpace/FunctionSpace/ GraphInducedSpace out of a MultiFieldFESpace/MultiFieldParamFEFunction (first scenario), or out of several input/output spaces/ParamFEFunctions (second scenario). FunctionSpace(f::MultipleSpaces)/GraphInducedSpace(f::MultipleSpaces) build the integration spaces matching the layout (and samples) of f.

Explicit architectural configuration for a NOMAD (Non-linear Manifold Decoder) network. NonlinearROMs.RolloutData — Type
struct RolloutData{A,B<:AbstractVector,C<:Union{Tuple,AbstractVector}}
  data::A
  times::B
  steps::C
end

RolloutData(data,times,step=2)

Temporal-bundling layout (Brandstetter et al.) of transient data (a FeatureBundle of transient ParamFunctions, or a TransientParamFESolution) for an autoregressive neural operator. steps are pointers into times (indices, not time values) cutting them into nc disjoint clusters of step consecutive times, steps[c]:steps[c+1]-1; each cluster is split into two halves (stages) of step÷2 time slots each. A trailing incomplete cluster is dropped, with a warning.

Evaluated into an InputSpace/OutputSpace, RolloutData produces TwoStageBuckets: the time slots of a stage are stacked along the channel axis (slot-major), and the samples are ordered cluster by cluster, sample (c-1)*np+ip holding cluster c of parameter ip.

NonlinearROMs.RolloutNeuralSolver — Type
RolloutNeuralSolver(model::NeuralModel;warmup_epochs=0,λ=1.0,kwargs...)

NeuralSolver for autoregressive (rollout) training on RolloutData, with temporal bundling and the pushforward trick of Brandstetter et al.; kwargs are those of NeuralSolver. Writing F₁ᶜ,F₂ᶜ for the features and s₁ᶜ,s₂ᶜ for the states at the two stages of cluster c, the network N maps [x;F;previous state block] to the next state block, and is trained on the loss

\[ℓ(N([x;F₂ᶜ;s₁ᶜ]),s₂ᶜ) + λ\,ℓ(N([x;F₁ᶜ;\mathrm{sg}(N([x;F₂ᶜ⁻¹;s₁ᶜ⁻¹]))]),s₁ᶜ),\]

summed over all clusters (the second term for c ≥ 2 only), sg being a stop-gradient. For the first warmup_epochs epochs only the one-step term is trained. The trained operator is evaluated by solve(solver,op,input_space, initial_output_space), which rolls the network out from the initial state (see rollout).

NonlinearROMs.WeightedSimpleDiGraph — Type
WeightedSimpleDiGraph{Ti<:Integer,Tv<:Real} <: Graphs.AbstractSimpleGraph{Ti}

A directed graph with the same internal layout as Graphs.SimpleDiGraph{Ti} (a pair of sorted forward/backward adjacency lists), extended with a scalar weight attached to every directed edge from both endpoints' perspectives:

  • fweights[s][k] is the weight of the edge s -> fadjlist[s][k], stored alongside fadjlist for O(1) access when iterating outneighbors(g,s).
  • bweights[d][k] is the weight of the edge badjlist[d][k] -> d, stored alongside badjlist for O(1) access when iterating inneighbors(g,d).

By default add_edge! stores the same value on both sides of an edge; pass distinct forward/backward weights explicitly for asymmetric couplings (e.g. upwinded or non-symmetric operators on a mesh).

NonlinearROMs.assemble_norm — Method
assemble_norm(op::AssembleOperator,f) -> AbstractMatrix

Gram matrix of the GridapROMs norm op (ℓ2(), L2(), H1(), ...) on the point layout of the (D,N,K) data living on f, rather than on f's dofs:

  • single field: (N,N), restricted to one representative dof per point (the norms are component-wise, so every component shares this same matrix);
  • multi-field: (D*N,D*N), block-diagonal with one block per channel, each field's matrix being extended by zero from its own points to the union of every field's points (the layout of a multi-field MultipleSpaces).

NonlinearROMs.attention — Method
attention(scores::AbstractVector,g::AbstractGraph) -> per-edge weights

Normalizes scores (one per edge) into attention weights: a numerically-stable softmax over the scores of every edge sharing the same destination vertex (a per-vertex group, not a single global softmax over all edges).

Same NNlib.scatter approach as scatter_data, applied to the two group reductions a segmented softmax needs (max-per-group, then sum-per-group of the shifted exponentials) instead of three sequential per-edge scalar loops, for the same Reactant/MLIR-scaling reason. scores/dsts are already 1-D (one entry per edge, no channel/sample axes), so no permutedims wrapping is needed here, unlike gather_data/scatter_data.

source
NonlinearROMs.blockwise — Method
blockwise(f,meas::MultipleMeasure,edata::AbstractInputData...) -> AbstractInputData

Evaluates f(ldata...,m) on every local measure m of meas, where ldata are the edge-indexed edata restricted to the edges (and, for sample-stacked spaces, to the samples) of m, and f returns local vertex-indexed data. The local results are then expanded onto the global vertices via l_to_lcoord_to_coords (a placement, these maps being injective, built on NNlib.scatter on plain index arrays so that nothing is unrolled per edge under a Reactant trace), and summed (shared samples) or concatenated along the sample axis (one block of samples per local space).

source
NonlinearROMs.gather_data — Method
gather_data(vals,g::AbstractGraph) -> per-edge array

Pure indexing (src.(edges(g))/dst.(edges(g)) are computed from g alone, never from vals, so they're ordinary concrete arrays even when vals is a Reactant-traced tensor): no edge ever needs to accumulate more than one value, unlike scatter_data, so a plain vectorised gather suffices and no per-edge Julia loop is traced. A loop here would otherwise get unrolled into one set of MLIR ops per edge – fine at boh.jl's ~200 edges, but a multi-field graph (e.g. Stokes' combined velocity+pressure point cloud) can have tens of thousands, enough to exhaust Reactant's internal MLIR symbol-naming budget.

Each edge's output column is the source node's features stacked on top of the destination node's (channel axis doubles, 2*size(vals,1)), not a separate output column per endpoint (NNlib.gather, unlike scatter, never accumulates, so there's no op/dstsize to combine src/dst into one pass – two separate gathers are needed, one per endpoint, then vcat'd along the channel axis).

NonlinearROMs.get_node_masks — Method
get_free_dof_to_comp(f)
get_free_dof_to_point(f)

Metadata-independent replacements for reading off a SingleFieldFESpace's NodeToDofGlue (only ever built by Gridap for order-1 Lagrangian spaces; any higher order, e.g. the quadratic velocity space in a Taylor-Hood Stokes pair, gets the more general CompressedCellConformity instead, which has no precomputed dof/node glue arrays). Both are derived generically via a cell traversal, so they work for any UnconstrainedFESpace regardless of which CellConformity it was built with.

get_free_dof_to_point plays the role NodeToDofGlue.free_dof_to_node used to: rather than trying to reconstruct Gridap's internal mesh-node numbering (which isn't well-defined once higher-order dofs, e.g. edge midpoints, are involved), free dofs are grouped directly by their (exact) physical coordinate – dofs at the same point (e.g. one per vector component) necessarily share one.

NonlinearROMs.kv — Method
kv(k,v,meas::InducedMeasure)

Explicit κ_θ(x,y,...)·v(y) product in Kovachki et al.'s (K_t v)(x) = ∫ κ_θ(x,y,...) v(y) dy: k is κθ's output, a flattened dout*din-vector per evaluation point (edge, for a graph measure), and v is the running hidden state at the SAME points k was evaluated at (gathered to match k's per-edge/per-point indexing by the GraphMeasure method below, mirroring how `kernelinputgathers data for feedingκθitself). NonlinearROMs.replace_space — Method
replace_space(op::NeuralOperator,space::DiscreteSpace) -> NeuralOperator

Returns op with every kernel's measure rebuilt on space, keeping the trained parameters, states and normalisation: this is how a kernel operator trained on some point cloud(s) is evaluated on a new one. space must be of the same kind as the training one (graph-induced for a model trained on graphs, also when the training space is a MultipleSpaces of graphs, e.g. a moving geometry), and the inputs must then live on get_coords(space).

NonlinearROMs.rollout — Method
rollout(op::NeuralOperator,data::TwoStageBuckets,state::AbstractInputData) -> TwoStageBuckets

Autoregressive evaluation of a network trained by a RolloutNeuralSolver: starting from the initial state block state (one sample per parameter), every cluster c is advanced as ŷ₁ᶜ = N([x;F₁ᶜ;ŷ₂ᶜ⁻¹]), ŷ₂ᶜ = N([x;F₂ᶜ;ŷ₁ᶜ]), with ŷ₂⁰ = state. data and state must be normalised; the predictions are fed back, and returned, normalised.

NonlinearROMs.scatter_data — Method
scatter_data(vals,g::AbstractGraph) -> per-vertex array

Sums vals (one column per edge, in edges(g) order; leading axes = channels) into its destination vertex: out[...,dst(e_k)] += vals[...,k]. The shared building block behind both the uniform-mean aggregation used by _integration(a,::AbstractGraph) (plain GNO) and the softmax-weighted aggregation in attention/AttentionKernel (HAMLET): the only difference between the two is what's summed – vals itself for a fixed 1/degree weight, or α .* vals for a learned, data-dependent one.

Unlike gather_data, this genuinely needs to accumulate (several edges can share a destination vertex), so a plain vectorised getindex-style gather doesn't suffice – NNlib.scatter(+,...) is used instead (the same primitive GNNGraphs.jl builds its own message passing on), rather than either a per-edge loop (gets unrolled into one set of MLIR ops per edge under a Reactant/Enzyme trace – fine at boh.jl's ~200 edges, but a multi-field graph, e.g. Stokes' combined velocity+pressure point cloud, can have tens of thousands, enough to exhaust Reactant's internal MLIR symbol-naming budget) or the previous dense (nv,ne) incidence-matrix matmul (whose own construction was a setindex!-based loop with the same problem, needing a separate precomputed-and-cached path to stay off the traced call stack entirely). NNlib.scatter's own edge axis is the array's last dimension, not vals's second (see AbstractInputData's (D,N,K) layout), hence the permutedims wrapping either side of the call.

NonlinearROMs.train_model! — Method
train_model!(train_state,dataloader,stats,lr_scheduler,loss,to_device_batch;logger) -> NeuralOperator

Generic Lux/Reactant/Enzyme training loop shared by every architecture in this package. to_device_batch maps one raw batch yielded by dataloader to whatever loss expects as its data argument (already moved to XDEV) — DeepONet pairs each batch with a fixed set of trunk query points, NOMAD's coordinates are already part of the per-row batch, and a plain reconstruction network (AutoEncoder/AutoDecoder) just needs (x,x). loss defaults to Lux.MSELoss(); pass a custom (model,ps,st,data) -> (loss,st,stats) function for anything else (e.g. a VAE's reconstruction+KL loss). stats is the normalisation bundled into the returned NeuralOperator.

NonlinearROMs.visualise — Method
visualise(dir,uh,ûh;trian,dir_name="plot",variable_name="uh",param_id=1)

Writes the true field uh, the prediction ûh and their difference for the param_id-th parameter to joinpath(dir,dir_name), as the cell fields variable_name, "approx_"*variable_name and "err_"*variable_name (one per field, suffixed _field<i>, for multi-field functions). For a steady uh (a ParamFEFunction) a single .vtu file is written; for a transient uh (a TransientParamFESolution), ûh stores every (parameter,time) pair with the parameter index running fastest, as returned by to_element on a rollout prediction, and one .vtu file per time step is written, collected into a .pvd time series.
